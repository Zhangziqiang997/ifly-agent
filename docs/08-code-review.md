## 2. 架构审查

### 2.1 优点

- ✅ **三层分离清晰**：parser（L1）、matcher（L2）、advisor（L3）各自独立，通过 engine 串联
- ✅ **数据层解耦**：data_loader 封装了 JSON 读写，引擎不直接依赖文件系统路径
- ✅ **配置外置**：config.py 统一管理环境变量，API Key 不从代码中泄露
- ✅ **降级设计**：AI API 不可用时自动降级到本地缓存，系统不崩溃
- ✅ **单一批量调用**：所有 uncertain 参数打包为 1 次 API 请求，避免 N+1 问题

### 2.2 改进建议

- ⚠️ **缺少接口抽象**：当前 engine 直接 import parser/matcher/advisor，建议加一个 `AnalysisPipeline` 类统一管理流程
- ⚠️ **无日志系统**：当前用 `print()` 输出，建议引入 `logging` 模块支持等级过滤和文件输出
- ℹ️ **Streamlit 状态管理**：当前用 `st.session_state` 单例，功能简单时够用，复杂后建议抽到独立的 Session 类

## 3. 代码质量审查

### 3.1 文件逐评

#### `config.py` ✅ 优秀
- 单文件职责：读取环境变量
- 有默认值兜底
- 4 行代码，零依赖

#### `data_loader.py` ✅ 优秀
- 4 个函数各自独立，命名语义化
- `load_competitors()` 自动发现目录下所有 JSON，扩展性好
- 所有函数有 FileNotFoundError 兜底
- 建议：加类型注解（已函内有说明但未使用 `typing` 模块）

#### `parser.py` ⭐ 核心文件，质量最高
- `extract_numeric()` 覆盖了中英文数字+单位模式
- `find_best_match()` 用 scoring 系统替代了原来的 unit-only 匹配，修复了关键 Bug（[Bug-01]）
- `keyword_overlap()` 使用 Jaccard bigram，简单有效
- 建议：
  - ⚠️ `extract_numeric()` 的正则列表硬编码，新增单位需改代码 → 建议抽为配置
  - ℹ️ `_name_overlap()` 的字符集交集对中文效果一般，可考虑用 jieba 分词

#### `matcher.py` ✅ 简洁正确
- `identify_controller()` 算法与 SPEC 伪代码一一对应
- 返回结构包含完整的 hits 和 anomalies 详情
- 建议：
  - ℹ️ 当前仅统计"独有特征命中数"，可考虑加权（★废标项权重更高）

#### `advisor.py` ✅ 设计合理
- 单次批量调用，效率高
- Prompt 包含讯飞全量能力目录 + 防错配指令，质量好（[协作 #08]）
- API 成功后自动保存降级文件，兼顾性能和可靠性
- 建议：
  - ⚠️ `TIMEOUT=30` 略长，Demo 场景可接受，生产环境建议 10s
  - ℹ️ 降级文件路径硬编码 `data/samples/demo-result.json`

#### `engine.py` ✅ 流程清晰
- `run_analysis()` 严格按 L2 → L1 → L3 执行
- positive/negative 都在 L1 判定，只有 uncertain 才送 L3
- summary 统计自动计算
- 建议：
  - ⚠️ negative（程序判定）会重复送 AI（为了生成建议），导致这些条目出现在 uncertain_items 中但已在 matching 中有条目 → 当前逻辑有潜在重复

#### `app.py` ✅ UI 直观
- 两页面设计（总览 + 对比表）符合 Demo 三页面的需求（合并了 Page 2+3）
- 筛选器、展开卡片、颜色标记交互完整
- 状态管理清晰
- 建议：
  - ℹ️ 当前仅支持 JSON 上传，后续需扩展 PDF/Word
