# AI 投标决策中心：演示分析闭环设计

## 目标

在独立静态页面 `ai-bidding-decision/` 中补齐一个可路演的闭环：PDF 上传并模拟入库、启动 AI 分析、查看固定的分析报告。保留现有蓝色视觉风格，不修改 `kc_aiHackson`。

## 页面与状态

### 首页（`index.html`）

1. **PDF 上传与知识库入库**
   - 仅接受 `.pdf` 文件；选择其他类型时提示“仅支持 PDF 文件”，不开始流程。
   - 选择 PDF 后立即展示文件名和“正在解析 PDF”。
   - 固定 3 秒后展示“解析完成，参数已进入知识库”。知识库统计仅作视觉更新，刷新页面后回到初始演示状态。
   - 该流程不读取文件内容、不访问接口、不真实解析。

2. **AI 分析**
   - “开始 AI 分析”初始可点击，与是否上传文件无关。
   - 点击后按钮进入进行中状态，页面显示“AI 正在分析”，固定 10 秒。
   - 分析期间不允许重复启动；结束后显示“分析完成”。

3. **报告入口**
   - “查看文档 AI 分析报告”初始灰色禁用。
   - 仅在 10 秒分析完成后改为蓝色可点击。
   - 点击进入 `report.html`。上传 PDF 不改变报告内容；它只为“参数已进入知识库”的演示叙事提供状态反馈。

### 报告页（`report.html`）

- 使用固定的 mock 数据，按 `kc_aiHackson` 已有分析结果的字段和语义展示：整体置信度、可疑/控标倾向、正偏离数量、负偏离数量、风险项、匹配依据与应对建议。
- 视觉沿用 `ai-bidding-decision` 的蓝色、浅灰背景、圆角卡片和微软雅黑字体；不复制 `kc_aiHackson` 的页面样式。
- 提供“返回决策中心”。刷新报告页仍可查看固定示例报告。

## 技术边界

- 原生 HTML/CSS/JavaScript，无构建步骤和第三方依赖。
- 首页脚本以明确状态对象管理 `uploadStatus` 与 `analysisStatus`，定时器只用于本次演示。
- 报告数据放在独立脚本中，避免首页和报告页面耦合；后续接 API 时可替换为 `POST /api/analyze` 与 `GET /api/analyses/:id` 的返回数据。
- 所有动态文件名与文本以 `textContent` 写入页面，不插入未经处理的 HTML。

## 失败与边界状态

- 非 PDF：提示错误、保持未上传状态。
- 上传或分析进行中：对应触发按钮不可重复执行。
- 报告入口在分析完成前不可点击，并带有“请先完成 AI 分析”的说明。
- 不模拟网络、文件损坏或真实解析失败，因为本次明确是无后端的固定流程演示。

## 验收

1. 选择 PDF 后，能观察到 3 秒解析状态和“参数已进入知识库”。
2. 非 PDF 无法触发解析。
3. 点击“开始 AI 分析”后，报告入口在约 10 秒前保持禁用、完成后可点击。
4. 报告页能展示固定的正/负偏离、置信度和可疑项内容，且颜色体系与首页一致。
5. `node --check` 通过所有 JavaScript 文件；静态资源引用完整。
