## 1. 产品概述

### 1.1 产品定义

> **参数智能体**：面向智慧教育招投标场景的 AI 驱动参数分析系统。  
> 输入一份智慧黑板招标文件 → 自动识别控标方 → 逐条对比讯飞产品参数 → 标出正/负偏离 → 对不满足项生成应对建议。

### 1.2 目标用户与场景

| 用户角色 | 核心场景 | 痛点 | 期望产出 |
|----------|---------|------|---------|
| 讯飞售前/投标经理 | 拿到招标文件，需在 24h 内完成应标分析 | 人工对比 50+ 条参数耗时 2-3 天，容易遗漏 | 3 分钟内出完整应标分析报告 |
| 讯飞销售/渠道经理 | 招标意向公示期（通常 5 个工作日），需快速判断是否提出质询 | 看不出参数倾向性，缺乏质疑依据 | 控标方判定 + 独有特征清单 + 质疑话术 |

### 1.3 使用流程

```
教育局挂出智慧黑板项目招标书
        │
        ▼
投标经理上传招标文件（PDF/Word/Excel）
        │
        ▼
系统自动完成三层分析（3-10 秒）
        │
        ▼
输出完整应标分析报告：
  ① 控标方判定 + 置信度
  ② 逐条参数正/负偏离标记
  ③ 负偏离项的应对建议（改说辞/质疑/协调）
```

### 1.4 演示范围（比赛限定）

| 维度 | 范围 |
|------|------|
| 竞品厂商 | 希沃（SEEWO）、鸿合（HiteVision）、海康威视（HIKVISION） |
| 每家参数量 | Demo 精选 12-15 条核心硬件参数 + 3-5 条关键软件参数 |
| 讯飞参数 | 对应硬件 12-15 条 + 软件 3-5 条 |
| 数据来源 | `知识库3/` 下 69 个真实文件（含 docx/xlsx/pdf/md），经 AI 辅助提取为结构化 JSON |
| 演示用招标文件 | 预制的 1-2 份样例 JSON（模拟真实招标书结构） |
| **明确不做** | 全行业数据库、自动评分计算、移动端适配、用户登录/权限 |

## 2. 功能模块

### 2.1 模块一：数据层 — 参数知识库

**说明**：本模块是系统的数据基础，不是 Demo 演示路径的一部分，但必须在开发前完成。

**输入**：`知识库3/` 下的原始文件（69 个）
- 希沃：33 个文件（.docx / .xlsx / .pdf 为主）
- 鸿合：17 个文件（.md / .xlsx / .docx / .pdf）
- 海康：19 个文件（.md / .docx / .pdf）

**处理流程**：
1. AI 辅助读取各厂商产品参数文档
2. 人工选定每家 1-2 个旗舰型号作为对比基准
3. AI 将参数提取并归一化为统一 JSON 结构
4. 人工校验数据准确性（参数值、单位、来源）

**输出**：3 家竞品 + 讯飞的结构化参数 JSON（详见 §4 数据格式）

**厂商型号选择**：

| 厂商 | 选定型号 | 类型 | 选择理由 |
|------|---------|------|---------|
| 希沃 | FG86ED | 交互智能平板 | 最新 7.5 代，参数最全（有 xlsx 交集参数表） |
| 鸿合 | HB-H868S | 智慧黑板 | Markdown 格式最完整，参数覆盖硬件+软件 |
| 海康 | DS-D5186BCER | 旗舰红外算力智慧黑板 | 参数最详尽，独有特征明显 |
| 讯飞 | iFLY-EB860 | 讯飞智慧黑板 | （待补充真实参数后确认型号） |

### 2.2 模块二：招标文件解析

**输入**：招标文件（Demo 阶段使用预制 JSON 样例）

**处理**：
1. 识别参数条目（按序号/星号/三角标记分段）
2. 提取每条参数的核心要求文本
3. 归一化为统一结构（见 §4.2）

**输出**：结构化招标参数列表

**Demo 简化**：比赛演示使用 1 份预制 JSON 样例，不演示真实文件解析。文件解析能力作为技术储备在路演中提及。

---

### 2.3 模块三：控标方识别（横向对比）

**核心逻辑**：统计"独有特征"——招标中某条参数，市面上仅某一家厂商能满足。

**算法（纯程序，不调 AI）**：

```
对于每条招标参数：
  满足的厂商 = []
  对于每家竞品（希沃/鸿合/海康）：
    如果 竞品对应参数 ≥ 招标要求：
      满足的厂商.append(竞品名)
  
  如果 len(满足的厂商) == 1：
    标记为"独有特征"，归属 = 满足的厂商[0]
  
  如果 len(满足的厂商) == 0：
    标记为"异常：数据库中没有厂商满足此要求"
```

**输出**：
- 控标方判定 + 置信度（独有特征命中数 / 总有效参数数）
- 每家命中的独有特征清单（含具体参数名称和来源）
- "无人满足"的异常项提醒

**置信度解读**：

| 命中率 | 结论 | 动作建议 |
|--------|------|---------|
| > 60% | 高度可疑，强烈指向某一家 | 重点准备质疑材料 |
| 30-60% | 部分倾向，可能混合控标 | 逐条分析，关注独有特征项 |
| < 30% | 无明显控标倾向 | 正常投标准备 |

**为什么这关不用 AI？**
- 本质是"查表 + 计数"，SQL 一条 GROUP BY 就能做
- 程序跑：毫秒级，零额度消耗
- 如果用 AI 逐条判断：12 条 × 3 家 = 36 次调用，浪费且慢

### 2.4 模块四：讯飞参数匹配（纵向对比）

**核心逻辑**：双层架构 —— 程序粗筛处理 80%，AI 语义精判处理 20%。

#### 第一层：程序粗筛

| 匹配类型 | 方法 | 示例 | 适用占比 |
|----------|------|------|---------|
| 数值直接比较 | 正则提取数字 + 单位，比大小 | 要求 ≥ 500cd/m²，讯飞 520 → 满足 | ~40% |
| 单位归一化 | 映射表统一单位后比较 | 4K = 3840×2160 = 四倍高清 | ~15% |
| 关键词精确匹配 | 字符串包含 / Jaccard 相似度 | "护眼认证" → 匹配成功 | ~15% |
| 范围判断 | 提取区间值比较 | 要求 ≤ 28mm，讯飞 25mm → 满足 | ~10% |

**处理策略**：由于真实参数多为复合描述（一条含多个子指标），第一关需先将复合参数拆分为原子指标，再逐个匹配。拆分逻辑由 AI 辅助完成（一次性，不逐条调用）。

#### 第二层：AI 语义精判

**触发条件**（满足任一即送入 AI）：
- 程序粗筛后仍无法判定的参数（无公共关键词、无数值可比）
- 纯功能/软件类描述参数（如"支持 AI 一键备课"）
- 需要生成应对建议的所有负偏离项

**AI Prompt 模板**：

```
你是一个招投标参数分析专家。请判断以下招标参数与讯飞参数是否指向同一能力：

【招标要求】
{bid_param}

【讯飞参数】
{xunfei_param}

请返回 JSON：
{
  "match": true/false,
  "match_type": "exact" | "semantic" | "partial" | "none",
  "deviation": "positive" | "negative_wording" | "negative_real",
  "explanation": "一句话解释",
  "suggestion": "如果是负偏离，给出应对建议"
}
```

**输出分类**：

| 类型 | 标记 | 含义 | 下一步动作 |
|------|------|------|-----------|
| 正偏离 | 🟢 | 讯飞规格 ≥ 招标要求 | 加分项，标出优势 |
| 负偏离（说辞可改） | 🟡 | 能力有但描述不同 | AI 改写为招标对应说法 |
| 负偏离（真不满足） | 🔴 | 确实达不到招标要求 | AI 生成质疑话术 + 渠道协调建议 |

**额度估算**：
- 每条 AI 调用：~350 tokens ≈ $0.005
- Demo 规模：~5-8 条送入 AI = $0.04/次演示
- $20 额度可支撑约 500 次完整演示，绰绰有余

### 2.5 模块五：应对建议生成

**仅针对负偏离项**，按以下优先级生成：

| 优先级 | 策略 | 适用场景 | 示例 |
|--------|------|---------|------|
| P0 | **改说辞** | 讯飞有能力，但参数文档描述不同 | "屏幕镜像" → 改写为"无线投屏" |
| P1 | **质疑话术** | 讯飞确实不满足 | 从教学场景、生态完整性、法规标准三个角度生成质疑论点 |
| P2 | **渠道协调** | 无法通过说辞或质疑解决 | 标注"需联系渠道与业主沟通修改参数" |

**质疑话术三维度**：
1. **教学场景实用性**："日常教学中，5K 摄像头相比 4K 的实际感知差异极小，过度配置增加财政负担"
2. **生态与功能完整性**："单一硬件参数不代表整体方案优劣，讯飞在 AI 教学能力上有差异化优势"
3. **法规与标准依据**："现行国标/行标对此无强制要求，该参数涉嫌设置不合理投标门槛"

## 3. Demo 页面结构

### 页面 1：上传 & 总览

- 文件上传区（拖拽/选择招标文件）
- "开始分析"按钮
- 顶部结果卡片：
  - 控标方：希沃
  - 置信度：67%（命中 8/12 条独有特征）
  - 异常提醒：1 条参数无人满足
- 底部：各竞品独有特征命中分布（数字卡片 + 柱状图）

### 页面 2：参数对比表

- 表格列：序号 | 参数类别 | 招标要求 | 讯飞参数 | 偏离标记 | 匹配方式 | 操作
- 行颜色：🟢 绿（正偏离）/ 🟡 黄（可改说辞）/ 🔴 红（真不满足）
- 筛选器：全部 | 只看负偏离 | 只看正偏离 | 只看 AI 判定项
- 匹配方式标注："程序"或"AI 语义"

### 页面 3：应对建议详情

- 点击表格任一行 → 侧边/弹窗展开建议卡片
- 卡片内容：
  - 偏离类型 + AI 解释
  - AI 改写后的说辞（说辞可改）
  - 质疑话术（真不满足，三个维度）
  - 建议动作标签：🏷️ 改文档 / ⚖️ 质疑 / 📞 协调
