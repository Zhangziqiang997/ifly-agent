## 1. Demo 范围总览

比赛 Demo 不是完整产品，而是一条**最小可行演示链路**：上传招标文件 → 控标判定 → 参数对比 → 应对建议。以下按功能模块说明完整能力 vs Demo 实现。

| 模块 | 完整能力 | Demo 实现 | 取舍理由 |
|------|---------|----------|---------|
| **参数知识库** | 全量参数数据库，支持增删改查 | 每家精选 12-15 条核心参数，手写 JSON | 4 天建自动化入库系统不现实；12-15 条足够展示算法效果 |
| **招标文件解析** | 自动解析 PDF/Word/Excel，OCR 扫描件 | 读取 1 份预制 JSON 样例文件 | 解析引擎开发量大（尤其是 OCR），非产品核心价值；预制 JSON 不阻塞 Demo |
| **控标方识别** | 全量竞品实时对比 | 3 家 × 15 条查表匹配 | 算法逻辑完全一致，精度差异仅在数据量；路演可说明"数据量上去后算法不变" |
| **参数匹配（程序）** | 正则 + 单位归一化 + 关键词全覆盖 | 覆盖数值/单位/关键词三类匹配 | 80% 的参数在这一关有结论 |
| **参数匹配（AI）** | 全部 uncertain 项送 AI 语义精判 | 5-8 条送 AI | 额度充足（$0.04/次），且 AI 参与是关键评审维度 |
| **应对建议** | 全自动报告生成 | 点击负偏离行 → 展开建议卡片 | 交互式更适合 Demo，比静态报告更直观 |
| **Streamlit 页面** | 3 个完整页面（上传总览/对比表/建议详情） | 3 个页面，功能完整 | 主要工作量在引擎，UI 用 Streamlit 原生组件最快 |

## 2. Demo 演示链路

```
[页面1: 上传&总览]
  用户选择预制样例招标 JSON → 点击"开始分析"
  → 顶部：控标方判定卡片（控标方 + 置信度 + 独有特征数）
  → 底部：三家竞品命中分布

[页面2: 参数对比表]
  逐条展示 🟢正偏离 / 🟡负偏离(可改说辞) / 🔴负偏离(真不满足)
  标注匹配方式：程序 / AI 语义
  筛选器：全部 | 只看负偏离 | 只看正偏离

[页面3: 应对建议]
  点击任一负偏离行 → 侧边弹窗
  → 偏离原因 + AI 改写说辞（如果是说辞可改）
  → 质疑话术三维度（如果是真不满足）
  → 建议动作标签：🏷️ 改文档 / ⚖️ 质疑 / 📞 协调
```

## 3. 降级方案

| 风险 | 降级方案 | 触发条件 |
|------|---------|---------|
| AI API 超时/限流 | 预生成 AI 匹配结果 JSON，Demo 时直接读文件，不实时调用 AI | 现场网络问题或 API 不可用 |
| Streamlit 现场崩溃 | 播放备用录屏视频（`outputs/demo-video.mp4`） | 页面打不开或报错 |
| 演示数据有误 | 演示前由产品组做最终数据校验（每人抽查 5 条对照原文） | — |

**降级不影响演示效果**：预生成的 JSON 和实时 AI 调用的输出格式完全一致，评委看不出区别。
