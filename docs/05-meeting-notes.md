## 1. 核心需求摘录（PM 原话）

### 关于产品概念

> "我们要做一个参数智能体……教育局挂出来一份智慧黑板的招标参数，第一想要去识别这是到底是哪一家的参数，第二就是我们是否能匹配，或者说我们的响应程度是什么，不是不同的说法最后得出来的结果不一样。"

### 关于比赛演示规模

> "你不需要很多，你起码给它有一份展示的就可以了。我们就输一份希沃的数据库……大概是三家的，比如说一份鸿合的，一份希沃的，一份文香的，把这三家输进去……就做好一家的，比如说希沃和我的讯飞去对比。"

### 关于应对建议

> "如果我们哪里有不满足不能响应的，你需要给我提出一个修改建议……第一是修改我们的说辞，我们其实是有这个参数的，但是我们描述的方式不一样……第二就是我们根本就没有办法响应，我们去讲这个应该是让渠道去修正，还是说重新想办法。"

### 关于质疑话术（关键澄清）

> "不是造假……比如说他是五K的摄像头，我是四K的摄像头，我可以质疑说教学当中为什么要用那么高的摄像头？这不符不符合国家……从教学场景和应用上面，或者是我们整体的生态和功能上面，从法律法规上面去跟他去讲述。"

### 关于控标识别逻辑（关键澄清）

> "控标项就是只有我满足，别的厂商都满足不了……如果一个参数市面上几乎所有产品都是1080P，但招标要求5K，而市面上有且仅有一家的是5K，那这很可疑。这种情况我们不做评价，但是我们将它识别出来。"

### 关于招投标流程背景

> "首先都会挂意向，就是项目意向书……如果明显偏向某一个厂家，我就可以去质疑，质疑的话他就得去考虑……教育局不愿意担责。"

## 3. 领域知识速查（给没做过招投标的组员）

### 招投标时间线

```
教育局做预算 → 审批资金 → 挂"项目意向书" → 厂商质询期
    → 正式招标公告 → 厂商投标 → 专家评分 → 中标公示 → 质疑期
```

### 评分构成

| 分数类型 | 占比 | 谁控制 |
|----------|------|--------|
| 价格分 | ~30% | 最低价者得高分 |
| 技术分 | ~30-50% | 参数规格、产品能力 |
| 主观分 | ~20-40% | 评委主观判断 |

### 标书里的标记

| 标记 | 含义 | 后果 |
|------|------|------|
| ★ 星号 | 废标项 | 不满足 → 不能投标 |
| △ 三角 | 重大扣分项 | 不满足 → 扣 3 分 |
| 无标记 | 普通项 | 不满足 → 扣 1 分 |

### 控标是什么意思？

> 招标方（业主/专家）在写招标参数时，故意写入某些**只有特定厂商能满足**的规格要求，使得其他厂商无法投标或投标时处于劣势。这就是"控标"。
