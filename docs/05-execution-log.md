## 三、AI 协作记录

> 格式：`[序号] [阶段] → prompt 摘要 → AI 关键输出 → 人的判断/修改 → 结果`

### [01] [需求理解] 2026-07-24

**我（产品规划）输入了什么**：
> 把一段 3000 字的产品经理聊天记录贴给 Kooky，说："阅读一下上面的内容，这是我和产品经理的聊天，你从中提炼出来他具体的需求。他说的有点太过于松散。"

**AI 输出了什么**：
> 自动提炼出两大功能模块（竞品识别 / 参数匹配）、三类偏离结论（正偏离/负偏离可改/负偏离真不满足）、三种应对方案（改说辞/质疑话术/渠道协调），并明确指出"不做打分"和"不做全量数据库"。

**我做了什么判断 / 修改**：
> AI 的理解基本准确，但混淆了"横向对比"和"纵向对比"的逻辑。我在第二轮对话中纠正了："关于那个4K 5K摄像头的，其实不太对……" 让 AI 重新理解控标识别的本质——不是比讯飞能不能满足，而是找"市面上仅一家能满足"的独有特征。

**结果**：产出需求分析 → 扩展为完整 PRD

**额度消耗**：约 4 轮对话，预估 ~$0.15

---

### [02] [方案设计] 2026-07-24

**我（产品规划）输入了什么**：
> "怎么做参数的对比？比如说竞标文件中的某一项参数，我们产品对应的参数，这两个之间的对比要用 AI 大模型来执行，还是我们写一个程序呢？"

**AI 输出了什么**：
> 提出了"程序粗筛 + AI 精判"双层架构——第一关程序处理数值比较、单位归一化、关键词匹配（80% 参数），第二关 AI 处理语义理解（20% 参数）。并给出了伪代码示例。

**我做了什么判断 / 修改**：
> 认可双层架构方案。随后补充了"控标识别"的逻辑，让 AI 把架构从两层扩展为三层（第一关粗筛 → 第二关横向控标识别 → 第三关纵向讯飞匹配）。

**结果**：三层对比架构定案，写入 CLAUDE.md 和 03-technical-design.md

**额度消耗**：约 3 轮对话，预估 ~$0.10

### [04] [数据审视] 2026-07-25

**我（项目经理）输入了什么**：
> "我把你要的真实的数据粘贴过来了，这个叫知识库3的文件夹就是里面的真实数据，里面的数据很多，你来尝试的先看一下，不要动手，还是分析一下"

**AI 输出了什么**：
> 分析了 69 个真实文件后，AI 发现了 6 个关键问题：
> 1. **竞品变了**：原 Mock 数据的文香不存在，真实数据是海康威视
> 2. **参数不是原子值**：真实招标参数一条里嵌套 5-8 个独立指标，原 JSON Schema（单 value + unit）装不下
> 3. **每家多个型号**：鸿合 5 个、海康 4 个、希沃 3 个
> 4. **软件参数占比大**：白板软件 60+ 条、集控软件 40+ 条，纯功能描述无法数值比较
> 5. **希沃全是二进制文件**（xlsx/docx），解析难度远高于 Markdown
> 6. **缺少讯飞真实参数**

**我做了什么判断 / 修改**：
> - 确认文香 → 海康替换
> - 决定每家选 1 个旗舰型号
> - 决定重新设计数据模型（单值 → 参数组）
> - 要求 AI 先处理鸿合 Markdown（最易处理），希沃手动挑参数
> - 随后补充了讯飞数据 docx

**结果**：PRD v1.0 → v2.0（真实数据版），数据模型升级

**额度消耗**：约 2 轮对话，预估 ~$0.12

### [05] [SPEC 重构] 2026-07-25

**我（项目经理）输入了什么**：
> "指导老师说要注重 SPEC 工作流……在 PRD 当中你提到了很多，有些是制作 demo 有些是必须要实现。我不太明白这些乱七八糟的"

**AI 输出了什么**：
> 通过 Superpowers:brainstorming 技能，AI 提出了三种方案来拆分 SPEC 和 PLAN：
> - 方案 A：两份文档彻底分离
> - 方案 B：一份文档内部用章节墙分区
> - 方案 C：按 SPEC → PLAN → EXECUTE 三阶段重构全部文档
> 推荐方案 C，因为最符合 Superpowers 流程。

**我做了什么判断 / 修改**：
> 选择方案 C，但要求保留 PRD 名称方便团队沟通。PRD = SPEC。

**结果**：文档体系从 8 份精简为 6 份，01-PRD = 纯 SPEC，02-PLAN = Demo 范围

**额度消耗**：约 3 轮对话，预估 ~$0.15
