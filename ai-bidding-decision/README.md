# AI 投标决策中心前端交接说明

## 1. 当前交付是什么

`index.html`、`styles.css`、`app.js` 是独立的桌面端视觉演示页，直接打开 `index.html` 即可查看。它用于确认首页的信息架构和视觉，不是已经联通后端的完整系统。

当前页面中的导航和大部分按钮只展示 Toast 提示；**不能将其理解为对应业务已经完成**。后续开发应保留现有版式，将模拟数据替换为接口数据，并逐步接通以下核心闭环。

## 2. 推荐开发优先级：先完成两个闭环

指导意见要求首页重点信息不能只是“空壳”。不要平均开发全部导航页，先让评委能从首页看到真实数据、完成一次分析并查看结果。

### 闭环 A：参数知识库浏览（第一优先级）

**入口：** 首页“查看参数知识库”按钮，或左侧“参数知识库”。

**用户路径：**

```text
首页知识库统计 → 参数知识库列表 → 按厂商/分类筛选 → 参数详情与来源 → 返回首页
```

**使用现有数据：**

| 数据 | 路径 | 用途 |
|---|---|---|
| 讯飞参数 | `../data/xunfei/xunfei.json` | 讯飞智慧黑板的 15 条参数 |
| 希沃参数 | `../data/competitors/xiwo.json` | 竞品参数与控标特征对照 |
| 鸿合参数 | `../data/competitors/honghe.json` | 竞品参数与控标特征对照 |
| 海康参数 | `../data/competitors/haikang.json` | 竞品参数与控标特征对照 |

**首版页面最低要求：**

- 显示厂商、产品名、参数分类、参数名称、规格原文、指标数和来源文件。
- 支持“全部 / 讯飞 / 希沃 / 鸿合 / 海康”和分类筛选。
- 点击一条参数展开 `spec` 与 `indicators`；`star_mark`、`cert_required` 用标签展示。
- 首页的“99 / 100 组数据”改为基于实际 JSON 的统计；演示阶段可显示“本地样例参数”。

### 闭环 B：样例招标分析到应对建议（第二优先级，路演核心）

**入口：** 首页“开始 AI 分析”按钮；首版使用“样例招标文件”，不必先实现 PDF 解析。

**用户路径：**

```text
首页点击开始分析
  → 读取样例招标文件
  → 展示控标方识别、风险数和参数比对摘要
  → 打开 AI 研判结果/参数对比页
  → 点击负偏离项，查看解释与应对建议
```

**使用现有数据与逻辑：**

| 数据/逻辑 | 路径 | 用途 |
|---|---|---|
| 样例招标文件 | `../data/samples/sample-bid.json` | 12 条招标需求，包含 145° 视场角风险项 |
| AI 兜底分析结果 | `../data/samples/demo-result.json` | 负偏离说明与建议；无模型服务时保证可演示 |
| 三层分析入口 | `../src/engine.py` 的 `run_analysis()` | 粗筛、竞品控标识别、AI 语义研判的现有整合逻辑 |
| Streamlit 原型 | `../src/app.py` | 已有上传、分析报告、详细对比的业务展示参考 |

**首版页面最低要求：**

- “开始 AI 分析”显示加载态，完成后更新首页的风险数、控标方、参数数和报告状态。
- 结果页至少显示：招标条款、讯飞参数、判断、风险等级、解释和建议。
- 对 `negative_real`、`negative_wording`、`positive` 使用清晰且一致的状态颜色。
- 对样例中的“摄像头视场角 ≥145°”提供“查看依据 / 生成质疑话术”入口，形成可讲解的风险—证据—建议闭环。

### 可选闭环 C：质疑话术生成（在 A、B 完成后）

**入口：** 风险详情的“生成质疑话术”。

首版无需真的调用大模型：根据 `demo-result.json` 的 `explanation` 与 `suggestion` 填充一份可复制的质疑话术即可。后续再由后端接入模型服务。

## 4. 数据模型和联调约定

参数库 JSON 的基本结构：

```json
{
  "vendor": "科大讯飞（iFLYTEK）",
  "product": "讯飞智慧黑板 (旗舰款)",
  "params": [
    {
      "id": "XF-005",
      "category": "摄像",
      "name": "内置摄像头",
      "spec": "摄像头像素≥4800万像素……",
      "indicators": [{"name": "对角视场角", "value": 135, "unit": "degree", "comparator": "gte"}],
      "star_mark": true,
      "cert_required": true
    }
  ]
}
```

分析结果应至少统一为以下字段；后端可沿用 `src/engine.py` 的结果并在 API 层适配：

```json
{
  "project": "XX市教育局智慧教室建设项目",
  "controller_vendor": "希沃",
  "summary": {"total": 12, "risk_count": 5},
  "items": [
    {
      "seq": 5,
      "requirement": "对角视场角≥145度",
      "deviation": "negative_real",
      "explanation": "讯飞参数为≥135°，不满足要求。",
      "suggestion": "与招标方协调修改视场角要求，或确认实际规格。"
    }
  ]
}
```

建议接口（路径仅为前后端约定草案）：

| 方法 | 路径 | 返回内容 |
|---|---|---|
| `GET` | `/api/knowledge-base?vendor=&category=` | 厂商、分类、参数列表与统计 |
| `GET` | `/api/knowledge-base/params/:id` | 单条参数详情及来源 |
| `POST` | `/api/analyses/sample` | 运行 `sample-bid.json` 的分析并返回分析 ID 与摘要 |
| `GET` | `/api/analyses/:id` | 报告、风险项、偏离和建议 |
| `POST` | `/api/analyses/:id/items/:seq/script` | 指定风险条款的质疑话术 |

## 5. 前端实现建议

- 保留 `index.html` 的视觉布局，但将按钮的 Toast 替换为路由跳转或真实请求。
- 把 `app.js` 中的 `mockData` 移到独立 mock 文件；联调时使用 API 返回值替换，不要把接口响应直接拼入 `innerHTML`。需要转义文本或采用框架的安全渲染。
- 初期可由静态服务读取 JSON；正式联调时由 Python 服务提供 API，避免浏览器直接跨目录读取本地 JSON。
- 每个页面必须至少包含加载、空数据和请求失败状态，避免演示时出现白屏。

## 6. 演示验收清单

- [ ] 首页统计和风险摘要来自真实 JSON 或分析返回值，不再只是固定数字。
- [ ] 评委可点击“查看参数知识库”，看到讯飞与三家竞品的真实参数。
- [ ] 评委可从首页完成一次样例分析，进入结果页并查看至少一条风险的依据与建议。
- [ ] 左侧未实现的导航明确显示“建设中”或落到说明页，不出现点击无反应。
- [ ] 以上流程在无外网、无大模型服务时可通过 `demo-result.json` 完整演示。
