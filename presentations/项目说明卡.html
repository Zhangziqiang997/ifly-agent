模块一
问题定义		 目标用户 讯飞售前 / 投标经理：拿到招标文件后、投标准备阶段，需在数小时内完成 50+ 条参数对比
讯飞销售 / 渠道经理：招标意向公示期（通常 5 个工作日），需数据支撑提交质询
场景痛点 ① 人工对比耗时 2–3 天：逐条对比讯飞产品规格书，容易遗漏 ★ 废标项，一招致命
② 控标识别全靠经验：看不出参数倾向性，凭感觉判断，缺乏数据支撑不敢质疑
③ 公示期窗口极短：5 个工作日内须完成分析并提交质疑，手工根本来不及
④ 参数措辞差异大："无线投屏" vs "屏幕镜像"——说法不同但意思相同，人工容易误判
使用场景 ① 紧急应标：明天截标，需 2 小时内判断控标方 + 逐条对比讯飞参数 + 标出偏离
② 意向公示期质疑：发现可疑参数（如"摄像头视场角 ≥ 145°"），需有理有据生成三维度质疑话术
模块二
方案设计		 方案概述 三层对比架构，AI 只参与最需要语义理解的那一层：
第一层（程序）：单位对齐 / 数值大小判断 → 80% 参数秒级有结论
第二层（程序）：逐条比对 3 家竞品库 → 统计独有特征命中数 → 判定控标方 + 置信度
第三层（AI）：语义理解处理说法不同但意思相同的参数 → 批量打包 1 次 API 调用（12 条仅 1 次请求）
核心功能 ① 参数知识库：3 家竞品（希沃 / 鸿合 / 海康威视）+ 讯飞，每家 15 条核心硬件参数，覆盖 14 个分类
② 招标文件解析：支持 PDF / Word / Excel → 归一化为结构化 JSON（Demo 阶段使用预制样例）
③ 控标方识别：独有特征统计算法 → 置信度量化（>60% 高度可疑 / 30-60% 部分倾向 / <30% 无明显倾向）
④ 参数逐条匹配：🟢 正偏离 / 🟡 负偏离（可改写说辞）/ 🔴 负偏离（真不满足）
⑤ 应对建议生成：P0 改说辞 / P1 质疑话术（三维度：教学实用性 + 生态完整性 + 法规标准）/ P2 渠道协调
实现方式 全程 AI 结对编程（Kooky / Claude Code）：人出需求与验收、AI 写代码与自检
技术栈：Python 3.10 Streamlit DeepSeek v4-flash JSON 文件存储
架构：6 个 Python 文件（data_loader → parser → matcher → advisor → engine → app.py），零数据库、零容器
AI 调用策略：所有 uncertain 参数 批量打包为 1 次请求（杜绝 N+1） + 成功自动缓存为离线降级文件
成果形态 可运行 Web Demo（Streamlit 两页面：上传 & 总览 / 对比表含建议详情）+ 3 家真实竞品参数库（JSON）+ 样例招标文件 + 离线降级缓存（API 不可用时系统不崩溃）
模块三
AI 实践
闭环		 问题如何拆解 把"让 AI 帮忙做标书分析"拆为 6 个可执行任务，数据与引擎双线并行：
data_loader（数据加载）→ parser（数值比对）→ matcher（控标识别）→ advisor（AI 精判）→ engine（流水线串联）→ app.py（Streamlit UI）
双线之间以 JSON Schema 为唯一契约，原型开发组做数据、内容呈现组写代码，互不阻塞。
AI 如何参与 AI 承担了全流程工作：
① 需求提炼：3000 字 PM 聊天记录 → 30 秒输出二模块三结论的需求分析
② 架构设计：双层 → 三层架构迭代（人纠正"控标识别与参数匹配是两回事"）
③ 代码编写：6 个 Python 文件全部由 AI 生成，人审查后提交
④ 数据提取：5 个 Haiku 子代理并行扫描竞品文档，4 分钟提取 79 条参数声明
⑤ 文档重构：SPEC 工作流重组全部文档体系（PRD → SPEC + PLAN 分离）
⑥ 运行时调用：语义匹配 + 应对建议生成（每份标书仅 1 次批量 AI 请求）
人机如何协作 人负责目标定义与审美判断，AI 负责分析与生成。共迭代 10+ 轮：
需求理解 → 方案设计 → 项目骨架生成 → 数据审视（AI 发现"文香不存在，真实数据是海康"→ Schema 从单值升级为复合参数组）→ SPEC 工作流重构 → 并行数据提取 → 代码生成 → Bug 修复（unit-only 错配 → scoring 系统）→ UI 重设计（浅色 → Dark Navy）→ 端到端联调
每轮节奏：人提反馈 → AI 交新版本 → 人验收
效果如何验证 ① 代码审查 6 维度评分 ⭐⭐⭐⭐：架构清晰职责单一、代码精简（最长函数 ~65 行）、API Key 外部化安全满分
② 端到端测试通过：12 条招标参数全部分析完成，耗时 ~5 秒（含 AI 调用），远超"<10 秒"目标
③ 三层正确性验证：程序处理 ~80% 参数（数值比对 + 控标识别），AI 精判仅处理 ~20% 疑难项
④ 降级方案实测通过：API 不可用时自动读取缓存，系统不崩溃
用户价值 把应标分析从"2–3 天人工对比"变成"10 秒 AI 初筛 + 1 小时人工复核"；控标识别从"凭经验猜"变成"数据驱动 + 置信度量化"；质疑从"缺乏依据不敢提"变成"三维度话术有理有据"——让讯飞售前团队在投标战场上快人一步。
模块四
成果价值		 业务 / 组织价值 ① 零成本数字化应标工具：为讯飞售前团队提供免费、即开即用的参数分析能力
② 内容全部配置化：新增竞品厂商只需添加 JSON 文件，无需改代码；明年换品类、改参数只换数据
③ 沉淀方法案例："AI 协作 3 天产出招投标分析系统"的完整工作流，可复用到其他品类的参数对比场景
④ 小程序 / 集成路径清晰：Streamlit → 企业微信 / 钉钉嵌入，具备融入实际工作流的条件
模块五
后续优化		 创新与亮点 ① 三层分而治之：程序做程序的事（快 + 省钱），AI 做 AI 的事（语义理解），不滥用不缺席——这是架构设计上的核心判断
② 独有特征统计算法：控标识别从"凭经验"到"数据驱动"，每条结论可追溯到具体参数，可解释、可质疑
③ 零依赖纯 Python：667 行代码单机可跑，无需数据库 / 容器 / 云服务，JSON 文件即存储
④ 全程 AI 结对开发：作品本身就是"善用 AI"的最佳示范——人定义问题、判断结果；AI 辅助分析、生成、验证
⑤ 批量 AI 调用：N+1 问题优化为 1 次打包请求，$20 额度可处理 ~4000 条参数
当前不足 ① Demo 使用预制 JSON，真实文件上传解析（MinerU 集成）尚未完成——评委无法现场丢一份 PDF 进去跑
② 参数库仅 3 家 × 15 条，覆盖度有限；软件参数（白板 / 集控 60+ 条功能描述）无法数值比较，暂未进入引擎
③ AI 语义匹配准确率依赖 Prompt 质量，极端措辞或新品类参数可能误判
④ 无用户登录 / 历史记录持久化 / 报告导出（PDF / Excel）
⑤ 未做移动端适配

③ 增加 报告导出（PDF / Excel）+ 历史记录持久化
